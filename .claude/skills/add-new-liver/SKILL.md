# 新人ライバー追加フロー

## 概要

にじさんじに新人ライバーがデビューした際、サイトへ反映する一連の定型フロー。

**順序厳守**: 情報収集 → ファイル編集 → 検証 → ユーザー確認 → ローカルDB反映 → 本番DB反映 → コミット&PR。
【必須ゲート】【完了報告待ち】の手順では、ユーザーの返答を待ってから次へ進むこと。

## 手順

### 1. 情報収集（WebSearch）

- 収集項目: 名前 / 読み / ユニット名 / デビュー日 / YouTubeハンドル / 誕生日
- ハンドルは複数の独立ソースで照合する（nijisanji.jp 公式ニュース、Fandom Virtual YouTuber Wiki、にじさんじWiki (wikiwiki.jp)、ユーザーローカルVTuber統計 等）
- 誕生日は根拠ソースのURLを記録しておく（手順5で提示するため）
- 環境によっては youtube.com 等への直接アクセスがブロックされる。その場合は検索結果のクロスチェックで代替し、最終確認は手順5のユーザークリックに委ねる

### 2. `public/liver.json` 追記（末尾に追加）

- 国内ライバー: `aliasFirst` = ひらがな読みのみ、`aliasSecond` = `""`
- 名前が元々ひらがなの場合は `aliasFirst` に名前をそのまま入れる（例: でびでび・でびる）
- `isRetire: 0`, `isOverseas: 0`、`birthMonth`/`birthDate` は数値（不明なら `null`）

### 3. `app/(pages)/history/page.tsx` 追記

- 更新履歴リストの先頭に当日日付の `<div>` を追加（既存エントリの構造をコピー）
- 文言: 「「A」「B」のN名を追加しました。」

### 4. 検証

- ⚠️ リポジトリ全体の `pnpm format` は実行禁止（未フォーマットの既存ファイルを巻き込む）。`npx prettier --write <変更ファイル>` で対象ファイルのみ整形する
- `pnpm test` を実行。失敗があれば変更前（`git stash` で退避）と比較し、自分の変更起因かを判定する

### 5. ユーザー最終確認【必須ゲート】

以下のテーブルを提示し、ユーザーにクリックでの確認を依頼する。OKが出るまで先に進まない。

| 名前 | チャンネルURL | 誕生日 | 誕生日の根拠ソース |
| ---- | ------------- | ------ | ------------------ |

- チャンネルURL: `https://www.youtube.com/@ハンドル`
- 誕生日の根拠: 公式タレントページ `nijisanji.jp/talents/l/…` を優先、なければ Fandom Wiki 等。ワンクリックで検証できるURLをそのまま貼る
- 確認ポイントも明記する: チャンネル名に本人名+にじさんじ表記があるか / ハンドルが一致するか / 誕生日がソース記載と一致するか

### 6. ローカルDB反映【完了報告待ち】

- DB切替は `.env` 内のコメントアウト方式（本番 = Neon verceldb / 開発 = localhost:5432 の docker）
- `.env` を開発に切替 → `docker compose up -d` → `pnpm dev`（バックグラウンド起動）→ `open http://localhost:3000/liver_register`
- 赤背景の新規ライバー行の登録ボタンを押すようユーザーに促し、完了報告を待つ

### 7. 本番DB反映【完了報告待ち】

- `.env` を本番に切替 → dev サーバー再起動 → `open http://localhost:3000/liver_register`
- 新規ライバー行の登録ボタン**のみ**押すよう案内し、完了報告を待つ
- 完了後の後始末（必須）: 自分が起動した dev サーバーを停止し、`.env` を開発（ローカルDB）に戻す（以後の誤操作で本番DBに書き込むのを防ぐ）

### 8. コミット & PR

- feature ブランチ（`feat/…`）を切り、日本語 conventional commit でコミット
- push → PR 作成（base: `develop`）
- マージはユーザー本人が行う。`gh pr merge` は実行しない

## よくある失敗

| 失敗                                     | 対策                                             |
| ---------------------------------------- | ------------------------------------------------ |
| `pnpm format` で無関係ファイルを巻き込む | 変更ファイルのみ prettier                        |
| 本番DBに接続したまま作業終了             | 手順7の後始末（サーバー停止 + `.env` をローカルに）|
| ユーザー確認前にDB反映へ進む             | 手順5のOKを待つ                                  |
| DB反映前にPRを出す                       | 順序どおり: DB反映 → コミット&PR                 |
